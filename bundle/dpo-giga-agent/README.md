## Быстрая установка (Windows)

Распакуйте архив в короткий путь, например C:\DPO. Длина абсолютного пути папки комплекта — не более 80 символов; кириллица и пробелы допустимы. Требуются Windows x64, не меньше 8 ГБ свободного места (установленная копия занимает около 6,5 ГБ) и интернет. Права администратора не нужны.

### Установка из exe

Скачайте [установщик](https://github.com/LeonDeTur/giga-agent-test/releases/latest/download/dpo-giga-agent-setup.exe) и [файл SHA256](https://github.com/LeonDeTur/giga-agent-test/releases/latest/download/dpo-giga-agent-setup.exe.sha256). Установщик распаковывает комплект в C:\DPO\dpo-giga-agent (папку можно изменить, путь — не более 80 символов), создаёт ярлыки и затем предлагает запустить install.cmd: он скачивает компоненты и запрашивает ключ GigaChat. Права администратора не нужны. Удаление доступно через «Установленные приложения» или ярлык в меню «Пуск»; результаты в data\*\output сохраняются.

Перед запуском выполните в папке загрузки и сравните хеш с опубликованным файлом .sha256:

~~~cmd
certutil -hashfile dpo-giga-agent-setup.exe SHA256
~~~

Exe не подписан сертификатом подписи кода, поэтому браузер и Windows SmartScreen могут предупредить: «Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае»; сначала сверьте SHA256. Предупреждение о неизвестном издателе связано с отсутствием подписи и само по себе не является оценкой содержимого; SmartScreen также учитывает репутацию файла.

Дважды нажмите install.cmd, вставьте Authorization key GigaChat (developers.sber.ru → GigaChat API → «Ключ авторизации», scope GIGACHAT_API_PERS). Ввод скрыт. Первый запуск скачивает около 5,5 ГБ и занимает около 10 минут на быстром канале; загрузка модели может идти дольше. Повторный install.cmd занимает около 3 минут. После проверки откроется браузер. Вход по умолчанию: admin@example.com / giga_agent_admin; изменения задаются в .env. Результаты — data/*/output/.

Установщик предлагает ярлыки на рабочем столе и в меню Пуск. start.cmd запускает службы и браузер, stop.cmd останавливает, status.cmd показывает состояние. Службы продолжают работать после закрытия окна. reset.cmd просит подтверждение «ДА», удаляет БД, чаты и результаты; затем снова запустите install.cmd. Журнал установки: .giga_agent/run/install.log. Для автоматизации: powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Yes; ключ передайте через DPO_GIGACHAT_CREDENTIALS. При -Yes ярлыки создаются только с -Shortcuts.

На macOS/Linux: bash install.sh, bash start.sh, bash stop.sh. Нужны bash, curl, tar и SHA256 (sha256sum или shasum), поддержка tar.xz. Проверен только синтаксис; реальный запуск на этих ОС не проверялся.

Инструменты закреплены: uv 0.9.5, Node.js 22.14.0 LTS. При установке через install.cmd / exe установщик скачивает их сам в tools; заранее устанавливать их не нужно. SHA256 сверяется при установке с официальными checksum-файлами релиза. tools и .cache находятся внутри комплекта; системный PATH и реестр не меняются.

Автономная поставка: после успешных up и prefetch выполните tools\uv\uv.exe run dpo.py pack-offline. Архив dpo-giga-agent-offline.zip содержит tools и .cache, исключает .env, .venv, runtime, журналы и output. Файл OFFLINE включает UV_OFFLINE=1, HF_HUB_OFFLINE=1 и npm offline. На получателе повторно введите ключ. Интернет нужен GigaChat API. Перенос — только между одинаковыми ОС/архитектурами. Полнота кэша и переносимость uvx-окружений требуют проверки на новом пути; при отсутствии пакетов автономная установка завершится ошибкой. При размере больше 6 ГБ pack-offline отказывает: переносите tools и .cache отдельно. Автономный архив в этой среде не создан: сетевого прогрева не было.

Если Windows сообщает «Can't find Python file», FileNotFoundError или слишком длинный путь, перенесите комплект в C:\DPO и повторите установку; setup и install.ps1 отклоняют пути длиннее 80 символов.

# Учебный комплект giga-agent для ДПО

Комплект разворачивает локальный веб-интерфейс, три учебных проекта с готовыми инструкциями, доступ к учебным файлам через MCP, локальный Python и базу знаний «ДПО: закупки». Преподаватель открывает проект, показывает его инструкции и отправляет первое сообщение. Docker не требуется.


giga-agent — открытый проект [ai-forever](https://github.com/ai-forever/giga-agent), лицензия MIT. Зафиксирована версия **0.1.9**, ветка main, коммит **e02715ff2d1a29192f167d385647064a2ff5d2e5** (e02715f, 2026-10-05). Поставляется wheel с готовым интерфейсом: публикация PyPI отстаёт от этого коммита на 299 коммитов, а установка из GitHub требует сборки фронтенда, поскольку ui_dist не хранится в Git. Текст лицензии: wheels/LICENSE-giga-agent.


## Требования

- Windows 10/11, macOS или Linux; 64-разрядная система.
- Только при ручной настройке заранее установите [uv](https://docs.astral.sh/uv/getting-started/installation/) и [Node.js LTS](https://nodejs.org/en/download), доступные в терминале; для install.cmd / exe их скачивает установщик. Python 3.12 для приложения и 3.11 для Infinity uv загрузит при необходимости.
- Не меньше 8 ГБ свободного места; установленная копия занимает около 6,5 ГБ, лучше иметь 8–12 ГБ с запасом для Python, PyTorch, нескольких окружений и кэшей. Порог проверки install.ps1 — 5 ГБ; прохождение этой проверки не означает, что места достаточно. Модель эмбеддингов занимает около 1–2 ГБ, на слабом компьютере нужно больше времени и оперативной памяти.
- Интернет при первом запуске для пакетов и модели. Доступ к GigaChat API нужен при каждом запуске агента.
- Личный ключ GigaChat API с квотой для GigaChat-3-Ultra. Наличие ключа не гарантирует доступную квоту.

**Код в local_jupyter выполняется без изоляции**, поскольку safe_execution выключен. На Windows поддерживаемой ОС-песочницы нет. Используйте только учебные данные и доверенные инструкции. Аналогичная конфигурация без изоляции применяется этим комплектом и на macOS/Linux. Разрешение write_dirs нужно для встроенного write_file, оно не ограничивает произвольный Python на уровне ОС. Не открывайте порты в интернет. Запрос к GigaChat может содержать прочитанные агентом тексты.

## Быстрый запуск преподавателя

Для ручной настройки предварительно установите uv и Node.js; при установке через install.cmd / exe следуйте разделу «Быстрая установка (Windows)» выше.

1. Распакуйте архив и откройте терминал в папке с dpo.py и pyproject.toml.
2. В личном кабинете на [developers.sber.ru](https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-using-api) подключите GigaChat API для физических лиц, получите **Authorization key** для GIGACHAT_API_PERS.
3. Скопируйте .env.example в .env. Запишите ключ после GIGACHAT_CREDENTIALS=. Нужна одна строка Base64, без префикса Basic, кавычек < >, переноса строки или пробелов. Это ключ авторизации, не временный access_token.
4. Выполните:

~~~sh
uv run dpo.py up
~~~

Команда установит зависимости, подготовит конфигурацию, запустит пять сервисов, создаст проекты и документы, затем выполнит проверки без генерации ответов LLM. Ключ локального LiteLLM создаётся автоматически и остаётся в .env. Не включайте подробную отладочную печать HTTP.

5. Откройте **http://localhost:9090**. Войдите: **admin@example.com / giga_agent_admin**. Если меняли учётную запись в .env до первого запуска, используйте новые значения.
6. Откройте «Проекты» и выберите один из трёх проектов «Агент: …». Покажите описание и инструкции. Создайте новый чат внутри проекта и отправьте сообщение из сценария ниже.

На первом запуске загружается около 5,5 ГБ, установка занимает около 10 минут на быстром канале, на медленном — дольше; Infinity после загрузки кэша обычно поднимает модель примерно за 75 секунд. CLI ждёт Infinity до 30 минут, другие сервисы до 10 минут. Если ожидание закончилось, проверьте журнал, затем повторите start после stop.

Для подготовки класса заранее:

~~~sh
uv run dpo.py setup
uv run dpo.py prefetch
uv run dpo.py up
~~~

prefetch прогревает окружения uvx и кэш npx, скачивает модель. Сами зависимости приложения устанавливает uv run. Кэши находятся в .cache внутри комплекта; для переноса используйте pack-offline после успешной установки и prefetch.

## Как менять инструкции

В интерфейсе откройте проект и измените поле инструкций, сохраните и создайте новый чат. Это удобно для демонстрации влияния формулировок на результат.

Для воспроизводимого курса измените раздел «Инструкции» в нужном agents/01–03*.md и выполните:

~~~sh
uv run dpo.py seed
~~~

seed сопоставляет записи по имени, обновляет инструкции и настройки без повторного создания записей. Он перезапишет правки инструкций, сделанные только в интерфейсе. Не переименовывайте проекты без необходимости: другое имя считается другим проектом. {DATA_DIR} заменяется абсолютным путём при seed; на macOS/Linux разделители путей преобразуются автоматически. Первые сообщения не добавляются в инструкции.

Документы закупок при повторном seed пропускаются по исходному имени. Чтобы обновить изменённый документ, удалите его из базы знаний в интерфейсе и повторите seed. При переезде в другую папку выполните stop до переноса, затем setup, start, seed, check. Изменение учётных данных администратора в .env после создания БД не меняет пароль уже существующего пользователя.

## Команды и конфигурация

| Команда | Назначение |
|---|---|
| setup | Создать .env при отсутствии, проверить ключ, сгенерировать секрет LiteLLM, конфигурацию MCP и каталоги |
| prefetch | Скачать вспомогательные пакеты и модель в .cache внутри комплекта |
| start | Проверить пять портов, последовательно запустить сервисы, дождаться готовности |
| stop | Остановить деревья процессов, записанные этим экземпляром CLI |
| status | Показать PID, состояние процессов и TCP-портов |
| seed | Войти в API, настроить ресурсы, проекты и базу знаний |
| check | Проверить API, MCP, векторы, выбранные ресурсы, проекты и поиск RAG |
| up | setup → start → seed → check |
| reset | stop → удаление .giga_agent и содержимого data/*/output/, с подтверждением |
| reset --yes | То же удаление без вопроса |

Все порты задаются в одном месте — .env: GIGA_AGENT_PORT=9090, MCP_FILES_PORT=8101, MCP_FETCH_PORT=8102, INFINITY_PORT=8103, LITELLM_PORT=8104. После изменения портов выполните stop со старой конфигурацией, затем setup и start с новой. start всегда требует свободных портов. Если сервисы уже запущены, используйте seed/check отдельно.

GIGA_AGENT_PORT — существующий совместимый параметр giga-agent, его значение также передаётся в --port. Остальные четыре имени не совпадают с aliases настроек giga-agent. Префикс API фиксирован CLI: /api/agent.

PID-файлы и журналы находятся в .giga_agent/run/. CLI защищается от повторного использования PID проверкой времени создания и пути своего экземпляра. На Windows используется taskkill /T /F, на POSIX — новая сессия и завершение потомков.

## Решение проблем

**Занят порт.** CLI называет порт, сервис и, если ОС разрешает, PID и имя владельца. Остановите собственный прежний экземпляр командой stop или выберите пять других портов в .env. Чужие процессы комплект не останавливает.

**GigaChat: HTTP 401.** Проверьте Authorization key и GIGACHAT_SCOPE, затем seed. Убедитесь, что это ключ выбранного API и что у модели есть квота. check намеренно не расходует токены генерации и не доказывает доступность GigaChat; окончательная проверка — реальное учебное сообщение.

**Лишние символы ключа.** setup проверяет строгий Base64 от uuid:uuid и отказывается печатать значение. Уберите Basic, угловые скобки и пробелы. Не отправляйте .env коллегам.

**GigaChat embeddings: HTTP 402.** У бесплатного тарифа в исходном демо эмбеддинги были недоступны. Комплект использует локальные ru-en-RoSBERTa, а GigaChat — только для генерации. Не переключайте эмбеддинги на GigaChat для этой демонстрации.

**Почему между giga-agent и Infinity стоит LiteLLM.** LangChain OpenAIEmbeddings по умолчанию передаёт массивы токенов cl100k, а Infinity ожидает текст. LiteLLM декодирует массивы. check сравнивает прямой и проходящий через эту цепочку векторы: размерность 1024, косинус > 0.999.

**Сервер падает при первом Python на Windows.** В исходной версии проверка os.kill(pid, 0) может рассылать Ctrl+C консоли. CLI запускает сервер в CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW; дочерние Jupyter наследуют отключённый Ctrl+C. Не запускайте сервер вручную на занятии. Таймаут запуска Jupyter установлен в 90 секунд. CLI сам никогда не использует os.kill(pid, 0).

**Write access denied.** После перемещения папки повторите seed. В local_jupyter safe_execution=false и write_dirs содержит абсолютный путь data/. Зелёный индикатор песочницы сам по себе не доказывает право записи в учебный каталог.

**Долгий первый запуск.** Общая первая загрузка — около 5,5 ГБ. Следите за журналом Infinity: загрузка модели эмбеддингов (около 1–2 ГБ) — часть этого объёма. Не закрывайте терминал во время установки. Сделайте prefetch и пробный up заранее. Неудачная загрузка пакета или нехватка места требуют устранения причины и повторного запуска.

**Агент зацикливается после записи.** В каждой инструкции есть фраза: «После сохранения не ищи файлы в базе знаний — просто кратко отчитайся». Если агент продолжает работу, остановите текущую генерацию в UI, проверьте наличие выходных файлов, при необходимости попросите: «Файлы уже сохранены. Не вызывай инструменты, кратко сообщи итог». Новый запуск делайте в новом чате.

**up остановился на seed/check.** Уже поднятые сервисы сохраняются для диагностики. Посмотрите status и журналы, исправьте причину и повторите seed/check; для завершения выполните stop. При сбое самого start CLI пытается остановить начатые сервисы.

## Как проверить бандл

1. При ручной настройке установите uv официальной однострочной командой. Для install.cmd / exe предварительная установка uv и Node.js не нужна: установщик скачивает их сам в tools.

Windows PowerShell:

~~~powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
~~~

macOS/Linux:

~~~sh
curl -LsSf https://astral.sh/uv/install.sh | sh
~~~

Источник команд: [документация uv](https://docs.astral.sh/uv/getting-started/installation/). После установки заново откройте терминал. Установите Node.js LTS с [официального сайта](https://nodejs.org/en/download). Проверьте uv --version и node --version.

2. Распакуйте ZIP в новую папку. Для консервативной первой проверки используйте короткий путь вроде C:\Courses\dpo-giga-agent. Пробелы и кириллица передаются CLI как отдельные аргументы без shell-интерполяции, но полная проверка такой установки в среде сборки заблокирована; совместимость всей цепочки ещё нужно подтвердить. После успешной проверки ASCII-пути отдельно проверьте папку «Курс ДПО».

3. Перейдите в папку с dpo.py. Скопируйте .env.example в .env (PowerShell: Copy-Item .env.example .env; macOS/Linux: cp .env.example .env). Вставьте Authorization key с developers.sber.ru для GIGACHAT_API_PERS. Выполните uv run dpo.py up.

4. Успешный вывод check должен выглядеть примерно так. 15.11.2026 на Windows 11 получено **7 из 7 PASS**, включая «Ресурсы пользователя». Пример вывода:

~~~text
Итог | Проверка | Результат
PASS | Вход в API | вход выполнен
PASS | MCP dpo_files | инструментов: 16
PASS | MCP web_fetch | инструментов: 1
PASS | Локальные эмбеддинги | 1024 измерения; косинус 1.000000000
PASS | Ресурсы пользователя | модель, эмбеддинг и песочница активны и выбраны
PASS | Учебные проекты | 3 проекта; инструкции актуальны
PASS | База знаний | текстов: 5; поиск работает
Все проверки пройдены: 7 из 7. Можно начинать занятие.
~~~

5. Войдите на http://localhost:9090 с admin@example.com / giga_agent_admin. Запустите три проекта первыми сообщениями из сценария и сравните смысл результатов с data/instructor/expected_results.md и кратким списком выше. Проверьте также отдельный RAG-вопрос и наличие всех ожидаемых файлов.

6. Повторите uv run dpo.py seed. Число проектов и коннекторов в итоговой строке не должно измениться; учебных проектов должно быть три. Системные коннекторы MCP могут отображаться отдельно от REST-коннекторов GigaChat/OpenAI.

7. Завершите:

~~~sh
uv run dpo.py stop
uv run dpo.py status
~~~

Все пять сервисов должны быть остановлены, TCP-порты закрыты.

8. Для чистого повторного опыта выполните uv run dpo.py reset и подтвердите словом ДА. Для автоматического теста: uv run dpo.py reset --yes. Сброс сначала останавливает свои процессы, затем удаляет .giga_agent и файлы output/, сохраняет .env и input/. Ручной эквивалент: stop, удаление этих же каталогов/результатов, затем up. В PowerShell каталоги удаляют Remove-Item -LiteralPath с -Recurse; всегда предварительно убедитесь, что находитесь в папке учебного комплекта.

9. Если возник сбой, пришлите вывод uv run dpo.py status, сообщение об ошибке и файлы журналов .giga_agent/run/ (предварительно проверьте их на личные данные). **Не присылайте .env, базу SQLite, mcp-токены, ключи и скриншоты секретов.**

## Воспроизводимость и границы проверки

Wheel фиксирует исходный код и UI. MCP-прокси, fetch и filesystem server имеют точные версии. Зависимости самого приложения задаются upstream-ограничениями, Infinity/LiteLLM и ревизия модели пока не зафиксированы отдельными проверенными lock-файлами. В среде без доступа к PyPI создать новый uv.lock и проверить точные версии всей цепочки не удалось. Перед массовым развёртыванием нужен полный тест и фиксация окружений на машине с доступом к реестрам; один и тот же архив пока не гарантирует побитово одинаковые транзитивные зависимости.



Перед запуском учебного чата проверьте переключатель «Автономность» справа вверху окна чата. На новой БД он выключен: подтверждайте каждый шаг красной/зелёной кнопкой — это показывает, что агент собирается выполнить. Для непрерывного запуска включите «Автономность».
