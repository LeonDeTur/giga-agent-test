# Установка и сборка комплекта

## А. Установка для слушателя и преподавателя на Windows

### 1. Подготовка

1. Используйте Windows 10 или 11, 64-разрядную, с Windows PowerShell 5.1 или новее. Bootstrap загружает инструменты x64. Полное испытание выполнено на Windows 11; Windows ARM отдельно не проверена. Права администратора для штатной установки не требуются, но каталог должен быть доступен для записи.
2. Освободите место: установленная копия в испытании занимала около 6,5 ГБ; разумный запас — 8–12 ГБ. Скрипт проверяет только наличие 5 ГБ, чего недостаточно считать гарантией успешной установки. Inno Setup резервирует дополнительно 7 ГиБ.
3. Обеспечьте свободные локальные TCP-порты: 9090 — giga-agent, 8101 — MCP dpo_files, 8102 — MCP web_fetch, 8103 — Infinity, 8104 — LiteLLM. Службы слушают 127.0.0.1. Не публикуйте их в интернете.
4. Для первой установки нужен интернет: GitHub, nodejs.org, реестры Python/npm, Hugging Face и GigaChat. На Windows 11 первая установка заняла около 10 минут и загрузила около 5,5 ГБ. Сообщения старого README и установщика об около 2 ГБ занижены. Это измерение одного испытания, а не фиксированный размер загрузки.
5. В [личном кабинете GigaChat API](https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-using-api) подключите API для физических лиц и получите Authorization key для scope `GIGACHAT_API_PERS`. Нужен ключ авторизации Base64 от пары UUID, без `Basic`, пробелов и угловых скобок, а не временный access_token. Не передавайте ключ вместе с комплектом.
6. Выберите короткий путь, например `C:\DPO\dpo-giga-agent`. Абсолютный путь папки с `dpo.py` должен содержать не более 80 символов. Кириллица и пробелы разрешены кодом.

### 2. Способ 1: установщик EXE

1. Скачайте [dpo-giga-agent-setup.exe](https://github.com/LeonDeTur/giga-agent-test/releases/latest/download/dpo-giga-agent-setup.exe) и [dpo-giga-agent-setup.exe.sha256](https://github.com/LeonDeTur/giga-agent-test/releases/latest/download/dpo-giga-agent-setup.exe.sha256). Выпуск v1.0.0 опубликован; загрузка обоих файлов без авторизации и совпадение SHA256 проверены 15.11.2026.
2. В каталоге загрузки вычислите SHA256. Командная строка Windows (cmd):

```cmd
certutil -hashfile dpo-giga-agent-setup.exe SHA256
```

3. Сравните все 64 шестнадцатеричных символа с файлом `.sha256`; регистр букв значения не имеет. При несовпадении не запускайте файл. Контрольная сумма проверяет совпадение файла, но не заменяет подпись издателя.
4. EXE без настройки подписи не подписан. Для такой поставки следует ожидать предупреждение SmartScreen; точный вид зависит от политики Windows и репутации файла. Сборка не гарантирует отсутствие предупреждений. Если источник и сумма проверены и политика организации разрешает запуск, используйте предложенное Windows подтверждение запуска. Если политика запрещает запуск, обратитесь к администратору.
5. Запустите EXE, выберите короткий каталог. В конце оставьте включённым запуск установки компонентов. Мастер копирует исходный комплект и создаёт ярлыки; компоненты загружаются затем через `install.cmd`. Пропущенный шаг можно выполнить вручную из установленной папки.
6. Введите Authorization key в скрытом запросе и дождитесь завершения проверки. Установщик не включает готовые Python-окружения и модель.

### 3. Способ 2: ZIP или копия каталога

1. Распакуйте `dpo-giga-agent.zip` либо скопируйте каталог `bundle/dpo-giga-agent` в доступную для записи короткую папку. Не переносите чужие `.env`, базу и результаты.
2. Откройте cmd в папке с `dpo.py` и выполните:

```cmd
install.cmd
```

3. Введите ключ в скрытом запросе. После успешной установки можно согласиться на создание ярлыков.

Установка проверяет Windows, длину пути и свободное место; загружает uv 0.9.5 и Node.js 22.14.0 с проверкой официальных SHA256; сохраняет их в `tools`. Затем `uv run` создаёт Python-окружение и устанавливает зависимости. Ключ записывается в локальный `.env`. Команда `up` выполняет `setup`, `start`, `seed`, `check`: создаёт конфигурацию MCP и LiteLLM, запускает пять служб, настраивает учебные ресурсы и проверяет их. Браузер открывается после успешного завершения.

### 4. Способ 3: автономная поставка компонентов

1. Получите подготовленный `dpo-giga-agent-offline.zip` от преподавателя; порядок сборки приведён ниже. Обычные ZIP и EXE автономными не являются.
2. Распакуйте архив на такой же ОС и архитектуре в короткий путь. Сохраните `tools`, `.cache` и маркер `OFFLINE`. Выполните `install.cmd`, как в предыдущем способе, и введите собственный ключ.
3. Маркер включает `UV_OFFLINE=1`, `HF_HUB_OFFLINE=1`, `npm_config_offline=true`. Недостающие инструменты или пакеты приведут к ошибке вместо сетевой загрузки. Полнота кэша и переносимость окружений uvx на новый путь не подтверждены полноценным испытанием получателя; проверка на чистом пути обязательна перед занятием.
4. Интернет для генерации через GigaChat всё равно нужен. Это перенос зависимостей без повторной загрузки, а не полностью автономный чат.

### 5. Проверка и ежедневная работа

1. Успех — семь строк PASS и итог `Все проверки пройдены: 7 из 7`. Пять работающих процессов в status сами по себе этого не доказывают. На Windows 11 (сборка 10.0.26300) 15.11.2026 получено 7 из 7 как при первой установке (около 10 минут), так и при повторном запуске install.cmd (около 3 минут). Записи о 6/7 в README.md и CHECKLIST.md относятся к более раннему испытанию и устарели. Выполните проверку на своей машине, cmd:

```cmd
tools\uv\uv.exe run dpo.py check
```

2. Откройте http://localhost:9090. Учебный вход: `admin@example.com`, пароль `giga_agent_admin`, если до первого запуска не задали другие значения в `.env`.
3. Для обычного запуска из папки комплекта, cmd:

```cmd
start.cmd
```

4. Для состояния, cmd:

```cmd
status.cmd
```

5. Для остановки всех пяти служб, cmd:

```cmd
stop.cmd
```

6. Для удаления БД, чатов и результатов в `data/*/output/`, cmd:

```cmd
reset.cmd
```

Подтвердите словом `ДА`. `.env`, входные данные и кэши сохраняются. После сброса обычного start недостаточно: восстановите конфигурацию и ресурсы, cmd:

```cmd
tools\uv\uv.exe run dpo.py up
```

### 6. Обновление и удаление

1. Перед обновлением выполните `stop.cmd`. Сохраните отдельно `.env`, `.giga_agent` и нужные `data/*/output/` как резервную копию с секретами. Не распространяйте её.
2. Для EXE выберите прежний каталог: Inno Setup использует предыдущий путь. Для ZIP замените файлы новой поставкой в существующем каталоге. Штатная упаковка исключает `.env`, состояние и результаты; не заменяйте их содержимым чужой установленной копии.
3. Повторите `install.cmd`: зависимости обновятся, setup и seed повторно применят учебные настройки. Seed обновляет инструкции одноимённых проектов. Автоматическая миграция между произвольными версиями и откат в коде комплекта не предусмотрены; предварительная резервная копия необходима. После изменения пути повторный seed обновляет абсолютные пути.
4. Для удаления EXE используйте «Удалить учебный комплект» в меню «ДПО агенты». Деинсталлятор пытается остановить службы и удаляет в том числе `.env`, `.giga_agent`, окружения и кэши. Сохраните нужные данные заранее; пользовательские результаты могут остаться.
5. Для копии из ZIP сначала выполните `stop.cmd`, затем удалите папку комплекта и созданные ярлыки через Проводник. Отдельной команды uninstall в `dpo.py` нет.

### 7. Журналы и ошибки

| Симптом | Действие |
|---|---|
| Длинный путь | Перенесите комплект так, чтобы путь был не длиннее 80 символов. |
| Нехватка места | Освободите место с учётом около 6,5 ГБ установленной копии и запаса; повторите установку. |
| Занят порт | Проверьте status, остановите прежний экземпляр. Для чужого процесса выберите другие пять разных портов в `.env`, затем повторите setup, start и seed по второй инструкции. |
| Некорректный ключ | Замените GIGACHAT_CREDENTIALS собственным Authorization key; удалите Basic, пробелы и переносы. |
| Ошибка сети или SHA256 | Проверьте доступ к источникам; при несовпадении суммы не используйте загрузку, повторите получение из доверенного источника. |
| Долгий запуск Infinity | Смотрите `.giga_agent/run/infinity.log`; старт ждёт до 30 минут, остальные службы — до 10 минут. После устранения причины выполните stop, затем start. |
| up остановился на seed/check | Службы могут остаться запущенными. Проверьте status и журналы; повторите seed и check либо завершите stop. Сбой внутри start вызывает попытку остановки. |
| Write access denied | Повторите seed после переноса: write_dirs должен содержать абсолютный путь data, safe_execution — false. |
| Ошибка автономного кэша | Подготовьте и проверьте кэш на машине с сетью; не считайте обычный ZIP автономным. |

Основные журналы: `.giga_agent/run/install.log`, `dpo_files.log`, `web_fetch.log`, `infinity.log`, `litellm.log`, `giga-agent.log`; все сервисные журналы находятся в `.giga_agent/run/`. Предзагрузка пишет туда `prefetch-1.log` … `prefetch-6.log`. Перед передачей журналов проверьте их на секреты. Не отправляйте `.env` или БД.

## Б. Сборка и публикация для сопровождающего

### 1. Обычный ZIP

1. Работайте из корня репозитория с установленным Python. Команда из cmd:

```cmd
python bundle/package-phase2.py
```

2. Скрипт создаёт `bundle/dpo-giga-agent.zip` и `bundle/zip-contents.txt`, проверяет целостность ZIP, печатает размер и SHA256. Он исключает секреты, runtime, tools, кэши и журналы. Внимание: скрипт также переписывает `bundle/dpo-giga-agent/README.md` своими заменами; просмотрите diff перед публикацией. В рамках подготовки этих документов скрипт не запускался.

### 2. Автономный пакет

1. На целевой ОС и архитектуре установите комплект, успешно выполните up, затем предзагрузку из каталога с dpo.py, cmd:

```cmd
tools\uv\uv.exe run dpo.py prefetch
```

2. Повторно проверьте рабочую установку через check, остановите службы и создайте пакет, cmd:

```cmd
tools\uv\uv.exe run dpo.py pack-offline
```

3. Результат находится рядом с каталогом комплекта: для исходного расположения это `bundle/dpo-giga-agent-offline.zip`. Включены `tools` и `.cache`, добавлен `OFFLINE`; исключены `.env`, `.venv`, `.giga_agent`, output, `.downloads`, журналы, байткод и `litellm.yaml`. При суммарном размере включаемых файлов больше 6 ГиБ команда отказывает. README предлагает переносить tools и .cache отдельно; автоматической разбивки в коде нет.
4. Проверьте установку на новом пути и той же ОС/архитектуре с собственным ключом получателя. Кэши и модель не полностью зафиксированы по транзитивным версиям; обещать воспроизводимость без такого теста нельзя.

### 3. EXE и подпись

1. Установите Inno Setup 6. `ISCC.exe` должен находиться в PATH либо стандартном каталоге Inno Setup 6, перечисленном в build.cmd. Из корня репозитория, cmd:

```cmd
bundle\installer\build.cmd
```

2. Результаты: `bundle/dist/dpo-giga-agent-setup.exe` и `bundle/dist/dpo-giga-agent-setup.exe.sha256`. Без DPO_SIGN_CMD EXE не подписан.
3. Если есть доверенный сертификат подписи кода и signtool.exe из Windows SDK в PATH, задайте шаблон из installer/README.md, cmd:

```cmd
set "DPO_SIGN_CMD=signtool.exe sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /a $f"
```

4. Повторите команду сборки. Она передаёт Inno Setup `/DSIGN` и `/Sdposign=…`, подписывает установщик и деинсталлятор. Для кавычек в шаблоне Inno Setup используется `$q`. SHA256 считается после подписи. Самоподписанный сертификат не даёт доверия на чужом компьютере; подпись также не гарантирует отсутствие SmartScreen.

### 4. Тесты, версия и выпуск

1. Статические тесты запускайте из корня репозитория интерпретатором уже установленной копии комплекта, cmd:

```cmd
C:\DPO\dpo-giga-agent\.venv\Scripts\python.exe -B bundle\test_phase2.py
```

Тесты проверяют формат ключа, настройку safe_execution, длинный Windows-путь и состав автономного ZIP на фикстурах. Это не полная установка, сетевой тест или проверка подписи. Они создают временные файлы. Путь `C:\DPO\dpo-giga-agent` — пример установленной копии; укажите путь к своей копии. 15.11.2026 этим способом прошли 4 теста из 4.
2. Перед выпуском проверьте установку и 7/7 на чистой Windows, stop/status, повторный seed и нужные сценарии из CHECKLIST.md.
3. Для новой версии измените `AppVer` в `bundle/installer/dpo-giga-agent.iss` (сейчас 1.0.1): он задаёт AppVersion и поля VersionInfo. Согласуйте версию проекта в `bundle/dpo-giga-agent/pyproject.toml` (сейчас 1.0.1) и тег выпуска. Версия wheel giga-agent 0.1.9 — отдельная зависимость; её обновление требует отдельной проверки. Не меняйте AppId для обычного обновления. Автоматической команды повышения версии нет.
4. После проверки, из корня репозитория, с установленным и авторизованным GitHub CLI, опубликуйте EXE и сумму по существующему примеру, cmd:

```cmd
gh release create v1.0.1 bundle/dist/dpo-giga-agent-setup.exe bundle/dist/dpo-giga-agent-setup.exe.sha256
```

Для следующего выпуска замените тег на выбранную версию. Пример команды из installer/README.md не загружает обычный или автономный ZIP; автоматическая публикация этих архивов в перечисленных исходниках не предусмотрена. Включите их как дополнительные вложения через страницу выпуска при необходимости. Убедитесь, что latest указывает на нужный выпуск и имя EXE сохранено для ссылки слушателей. Команды публикации здесь приведены как инструкция, а не выполнялись.
